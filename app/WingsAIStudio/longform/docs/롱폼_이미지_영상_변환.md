# 롱폼: 이미지 → 영상 동작 정리

롱폼(`app/WingsAIStudio/longform`)에서 “이미지를 영상으로” 쓰는 흐름은 **서로 다른 두 단계**로 나뉩니다.

1. **이미지 → 짧은 영상 클립 (Image-to-Video, I2V)**  
   Replicate의 **WAN 2.2 I2V Fast**로 정지 이미지를 움직이는 짧은 비디오 URL로 바꿉니다.
2. **최종 롱폼 영상 (렌더링)**  
   TTS 오디오·자막·(이미지 또는 I2V 결과 URL)을 **Cloud Run 렌더 서비스**에 넘겨 한 편의 MP4로 합성합니다.

---

## 1. 이미지 → 영상 클립 (Replicate I2V)

### 구현 위치

- `app/WingsAIStudio/longform/actions.ts` — `convertImageToVideo(imageUrl, replicateApiKey, prompt?)`
- UI에서 호출: `page.tsx`의 `handleConvertSceneImageToVideo`, `handleConvertImagesToVideo`

### 모델·API

| 항목 | 값 |
|------|-----|
| **플랫폼** | Replicate |
| **모델 엔드포인트** | `POST https://api.replicate.com/v1/models/wan-video/wan-2.2-i2v-fast/predictions` |
| **헤더** | `Authorization: Bearer {Replicate API 키}`, `Content-Type: application/json`, **`Prefer: wait`** (동기 대기) |
| **입력 `image`** | 공개 접근 가능한 **이미지 URL** (생성된 이미지의 URL이 그대로 전달됨) |
| **입력 `prompt`** | 아래 “프롬프트” 참고 |

### 기본 프롬프트 (UI에서 커스텀 미전달 시)

함수 시그니처상 세 번째 인자 `prompt`는 선택이지만, **현재 롱폼 UI는 `prompt`를 넘기지 않습니다.**  
이때 사용되는 **고정 기본값**은 다음과 같습니다.

```text
cinematic slow motion, smooth camera movement, gentle zoom in effect
```

의미: 시네마틱한 슬로모션, 부드러운 카메라 무브먼트, 은은한 줌인.

### 결과 처리

- 응답 `output`이 문자열 URL이거나, 객체/`url` 필드, 배열 등 여러 형태를 코드에서 정규화해 **최종 비디오 URL 문자열**로 반환합니다.
- `output`이 바로 없으면 `prediction id`로 **최대 약 2분(2초 간격 × 120회)** 폴링합니다.

### 상태 저장 (렌더 시 참조)

| 모드 | Map | 키 | 용도 |
|------|-----|-----|------|
| **씬(장면) 기반 이미지** | `convertedSceneVideos` | `"씬번호-이미지번호"` (예: `1-2`) | 해당 슬롯에 I2V URL이 있으면 **이미지 대신 이 URL** 사용 |
| **문장(line) 기반 이미지** | `convertedVideos` | `lineId` (문장 ID) | 배치 변환 시 동일 |

프로젝트 저장/불러오기 시 이 Map들도 직렬화되어 복원됩니다.

### 필요한 설정

- **Replicate API 키** (설정/로컬스토리지 `replicate_api_key` 등 기존 앱 패턴과 동일)

## 2. 최종 영상으로 “합치는” 방법 (렌더 파이프라인)

I2V는 **클립 URL만 만들고**, 최종 타임라인은 **`handleRenderVideo`** 쪽에서 구성합니다.

### 씬 기반 렌더링 (`decomposedScenes` + 씬 이미지가 있을 때)

1. 대본·TTS·(선택) Whisper 등으로 **자막 타임라인**과 **각 구간 길이**를 맞춥니다.
2. `autoImages` 배열을 만듭니다. 각 항목은 대략 다음 형태입니다.  
   `{ id, url, startTime, endTime, keyword, motion? }`
3. **URL 선택 규칙 (핵심)**  
   - 키 `` `${sceneNumber}-${imageNumber}` ``로 `convertedSceneVideos`를 조회합니다.  
   - **값이 있으면** `url`에 **영상 URL**을 넣고, **없으면** 원본 **이미지 URL**을 넣습니다.  
   - 로그에 `"영상"` / `"이미지"`로 구분해 출력합니다.
4. 합쳐진 오디오·자막·`autoImages`·`characterImage` 등과 함께 **`/api/ai/render`**로 보냅니다.

### 일반(문장) 이미지 모드

- `convertedVideos.get(lineId)`로 I2V URL이 있으면 그걸 쓰고, 없으면 이미지 URL을 씁니다.

### 렌더 API (`/api/ai/render`)

- **역할**: Vercel API Route가 본문을 그대로 **Cloud Run** `POST {CLOUD_RUN_RENDER_URL}/render`로 전달합니다.
- **롱폼 본문 필드 예**: `audioBase64` 또는 `audioGcsUrl`, `subtitles`, `characterImage`/`characterImageUrl`/`characterImageGcsUrl`, **`autoImages`**, `duration`, `config`(기본 `1920×1080`, `fps: 30`).

클라우드 쪽 FFmpeg/합성 로직은 이 저장소의 Next 라우트가 아니라 **배포된 Cloud Run 서비스**에 있습니다. `autoImages[].url`이 **이미지**든 **짧은 mp4 URL**이든, 서비스가 URL 타입에 맞게 디코드·합성한다고 가정하는 구조입니다.

### 필요한 설정

- **`CLOUD_RUN_RENDER_URL`** (필수), 선택 **`CLOUD_RUN_AUTH_TOKEN`**
- 긴 영상은 Vercel 본문 크기 제한 때문에 **오디오 GCS 업로드** 등 별도 분기가 있습니다(렌더 라우트 주석·`page.tsx` 로직 참고).

---

## 3. 사용자 입장에서의 조작 순서 (요약)

1. 이미지 생성(씬 또는 문장별).
2. (선택) **“이미지를 영상으로 변환”** 실행 → Replicate **WAN 2.2 I2V Fast** 호출 → URL이 Map에 저장.
3. **영상 렌더링** 실행 → 각 구간에 대해 **변환된 영상 URL 우선**, 없으면 **정지 이미지**로 타임라인 구성 후 Cloud Run 합성.

| 내용 | 파일·심볼 |
|------|-----------|
| I2V 호출 | `longform/actions.ts` → `convertImageToVideo` |
| 씬 단위 변환 버튼 로직 | `longform/page.tsx` → `handleConvertSceneImageToVideo` |
| 문장 다중 선택 변환 | `handleConvertImagesToVideo` |
| 씬 모드 `autoImages`에 영상 URL 반영 | `handleRenderVideo` 내부 (`convertedSceneVideos.get`) |
| 렌더 프록시 | `app/api/ai/render/route.ts` |

---

## 5. 한 줄 요약

- **모델**: 이미지→클립은 **Replicate `wan-video/wan-2.2-i2v-fast`**.  
- **프롬프트**: UI 미지정 시 **`cinematic slow motion, smooth camera movement, gentle zoom in effect`**.  
- **최종 영상**: **Cloud Run**이 `autoImages`의 URL(이미지 또는 I2V 비디오)과 오디오·자막을 합성합니다.
